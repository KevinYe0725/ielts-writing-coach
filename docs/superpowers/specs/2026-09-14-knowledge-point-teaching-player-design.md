# Knowledge-Point Teaching Player Design

## Goal

将专项教学从“长文章分页”改成“按知识点逐步学习”的播放器，让用户在每一步都能明确知道正在提升什么能力，并在讲解后立即练习。

## User experience

- 每个步骤只呈现一个知识点：目标、解释、例句对照、练习或迁移。
- 内容可以动态生成 3–5 个知识点，不要求每节课固定出现相同章节。
- 顶部显示当前知识点标题与 `N / total` 进度。
- 底部提供上一步 / 下一步；URL 使用 `step` 参数支持刷新恢复。
- 练习答案和 AI 解析按 prompt id 保留，切换步骤不丢失。
- 详细内容在当前知识点内部展示；不因为分页而丢失必要解释。
- 训练卷入口只在最后一步出现，避免首屏分流。

## Content contract

现阶段不改后端接口，前端将现有 `FocusedTeachingData.sections` 和 `practicePrompts` 转换为步骤：

1. 将 Markdown 按空行分成语义块，并把标题和紧随其后的解释绑定，避免分页留下孤立标题。
2. 以约 440 字符为软上限合并语义块，同时合并过短的尾块，避免出现只有一行的页面。
3. 每个 section 的练习单独生成一个完整练习步骤，知识点页只负责解释和例句。
4. 未指定 section 的练习单独放在练习步骤。
5. 最后追加训练卷步骤。

如果 AI 后续返回显式 `knowledgePoints`，前端可替换适配器而不改变播放器交互。

## Visual direction

- 保留全局顶部导航。
- 主内容采用苹果字体体系：界面优先 SF Pro / PingFang，英文例句使用 Apple New York / Iowan Old Style 回退。
- 黑白灰为主，仅用一个强调色表示当前进度和主操作。
- 桌面端主内容保持 680–760px 阅读宽度，右侧仅保留轻量目录/进度。
- 当前步骤使用固定视口区域；内容过长时只在步骤内部滚动。
- 过渡动画只用于步骤切换和进度变化，遵守 `prefers-reduced-motion`。

## Accessibility and failure behavior

- 步骤导航使用按钮和可读的 `aria-label`，当前步骤提供 `aria-current` 或进度条语义。
- 切换步骤后将焦点移到当前步骤标题，不改变用户未触发的焦点。
- 空 section 不生成空白步骤；所有练习始终保留。
- URL step 非法时回退到第一步，超出范围时进入最后一步。
- AI 解析失败只影响当前练习的解析状态，不阻塞下一步和训练卷入口。
