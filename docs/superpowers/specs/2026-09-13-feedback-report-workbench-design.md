# 批改报告工作台设计

## 背景

当前批改页已经具备原文高亮、建议卡片、问题筛选、原文定位、段落诊断、专项教学入口和失败重试等能力，但首次打开时信息层级不够清楚。用户需要在大量标签、评分摘要和解释之间寻找第一处真正值得修改的问题；部分建议标题仍然使用“比较结构”“论证不足”等抽象表达，导致用户知道诊断方向，却不知道要改哪个词、补哪一步。

本设计把批改页定义为一个“报告工作台”：先帮助用户完成最有价值的修改，再提供完整学习证据。信息不被删除，而是通过快速修改和完整报告两层视图渐进展示。

## 目标

1. 用户在 10 秒内找到第一处可执行的修改。
2. 折叠状态下，用户就能看到问题证据和推荐改法。
3. 任意原文标记和建议卡片都能双向定位。
4. 默认只展开一条建议，用户可以再次点击收起。
5. 用户需要完整诊断时，可以一键切换到完整报告。
6. 黑白 OpenAI 风格贯穿批改页，颜色不再承担问题类型语义。
7. 现有 AI、持久化、筛选、重试、专项教学和移动端流程保持兼容。

## 非目标

- 本轮不改变 IELTS 评分算法、AI 服务接口、数据库表或任务状态机。
- 本轮不自动替用户接受修改，不把建议变成自动替换器。
- 本轮不删除详细解释、段落诊断或基础语法速查，只调整默认可见性和阅读顺序。
- 本轮不让历史报告重新生成；旧数据使用兼容展示，新报告使用新的内容约束。

## 设计原则

### 先行动，再解释

页面第一层只回答“先改什么”。每条建议的标题必须是用户可执行的动作或前后变化，例如“把 `older one` 改成 `adults`”，而不是只写“比较对象完整性”。

### 证据必须紧跟结论

建议卡片的折叠摘要直接显示原句片段和推荐改法。展开后才展示为什么、知识点和迁移规则，避免用户先阅读一段抽象描述再猜具体问题。

### 一次只处理一个问题

建议列表可以很长，但同一时间只展开一张卡片。点击当前卡片再次收起；点击另一张卡片时切换展开目标。点击快速模式未列出的原文高亮时，自动进入完整报告并打开对应建议。

### 颜色只做层级，不做判断

使用白色内容面板、浅灰页面背景、近黑主文字和中灰辅助文字。问题类型使用实线、虚线和点线下划线区分，避免用户把颜色误解为严重程度或正确/错误。

## 页面信息架构

```text
页面标题                                           [进入专项教学]

总体判断
一句话总结 · 已经做对的一点
四项评分（默认折叠）

这篇作文，先看这几处
[问题 1：具体动作] [问题 2：具体动作] [问题 3：具体动作]

┌ 原文 ─────────────────┬ 修改建议 ────────────────┐
│ 原题                   │ [快速修改] [完整报告]      │
│                        │ [全部] [需要改正] ...      │
│ 段落和高亮             │                            │
│                        │ 当前建议（仅一条展开）     │
└────────────────────────┴──────────────────────────┘

下一步：专项教学
范文锁定状态
```

## 默认模式：快速修改

新增 `ReportMode = "quick" | "full"`，页面初始值为 `quick`。

快速模式的建议集合由 `priorityFeedback(issues, targetIssueId)` 决定，最多显示三个不同技能的问题。现有问题筛选仍然有效；筛选后如果优先问题不属于当前分类，则回退到该分类的前三条，保证用户不会看到空白建议区。

建议卡片折叠状态包含：

```text
问题标题：把 “older one” 改成 “adults”
原句：children ... older one
→ Children ... adults
```

展开状态继续使用现有字段：`explanationZh`、`correctedVersion`、`knowledgePointZh`、`transferRuleZh` 和原文定位动作。`activeIssueId` 使用三态语义：未初始化时默认展开优先级第一条，`null` 表示用户主动收起，字符串表示当前展开项。

## 完整报告模式

完整模式使用当前筛选后的全部问题，不改变排序和定位逻辑。模式切换只改变建议集合，不重新请求服务器，也不清除当前筛选。若当前展开的问题在切换后仍存在，保持展开；若不存在，回到集合第一条。

顶部评分和段落诊断继续使用 `details` 折叠。完整报告模式是查看全部信息的入口，而不是另一个页面，避免用户丢失原文定位上下文。

## 建议卡片内容契约

### 标题

AI 生成的 `knowledgePointZh` 同时作为持久化后的用户标题，必须满足：

- 是具体动作或 before-to-after 变化。
- 尽可能包含原文词组、主语关系、比较关系或缺失的中间步骤。
- 不使用只有抽象名词的标题，例如“比较结构”“语法问题”“论证不足”。
- 保持短句，适合在建议列表中快速扫描。

### 折叠摘要

- `evidence` 显示原句最小可操作片段。
- `correctedVersion` 显示推荐改法的一行预览。
- 证据标签使用“原句”，不再使用含义模糊的“修改建议”。

### 展开解释

固定顺序为：为什么要改 → 参考改法 → 记住这个知识点 → 下次这样用 → 在原文中查看。可选润色保留“这项建议的作用”，不能写成错误。

## 原文与建议联动

- 原文 `mark[data-feedback-highlight]` 与建议卡片共享 issue id。
- 点击原文高亮时，若快速模式隐藏该 issue，先切换 `reportMode` 为 `full`，再展开卡片并滚动到建议。
- 点击建议卡片时，桌面双栏自动滚动原文高亮；移动端切换到原文 tab。
- 建议卡片按钮使用 `aria-expanded` 和 `aria-controls` 关联详情区域。
- 动态建议区域保留 `aria-live="polite"` 状态播报，不强制移动焦点。
- 再次点击当前建议只收起，不改变原文高亮的定位信息。

## 响应式布局

桌面宽度达到可调整报告阈值时，继续使用 `react-resizable-panels` 的左右双栏；建议面板标题、模式切换和筛选栏保持在面板顶部。窄屏继续使用“原文 / 修改建议”两个 tab，一次只展示一个面板。

移动端规则：

- 模式切换和筛选按钮可横向滚动但不产生页面横向溢出。
- 点击建议中的“在原文中查看”切换到原文面板并滚动到高亮。
- 详情卡片可以收起，收起后列表继续可见。
- 保持可见文字至少 12px，正文继续使用阅读字体。

## 视觉系统

批改页通过 AppShell 的 `monochromeShell` 继承黑白角色：

- `--desk-ink: var(--desk-mono-ink)`
- `--desk-paper: var(--desk-mono-paper)`
- `--desk-canvas: var(--desk-mono-canvas)`
- `--desk-blue`、`--desk-green` 映射到近黑色，仅保留现有语义类名兼容性。

建议卡片、筛选按钮和评分摘要使用边框与灰阶背景建立层级，不新增颜色。当前激活卡片使用更深边框和浅灰背景；焦点状态使用黑色轮廓。

## 错误和空状态

- 逐句建议仍在生成时，保留现有状态横幅和重试按钮；快速/完整模式不影响重试。
- 建议为空时，继续显示当前分类的空状态，不把它误报为失败。
- 旧报告没有可定位的 span 时，保留“无法安全标出单一位置”的说明和完整解释。
- AI 服务不可用时不隐藏已保存报告，也不阻止用户切换完整报告。

## 兼容性与文件边界

- `apps/web/src/app/feedback/page.tsx`：报告模式、建议集合、卡片展开状态、折叠摘要和联动事件。
- `apps/web/src/app/feedback/feedback.module.css`：模式切换、摘要预览、单卡展开和黑白层级。
- `apps/web/src/components/app-shell.tsx`：将 `/feedback` 纳入现有 `monochromeShell`，不改其他路由。
- `apps/web/src/lib/client/mock-service.ts`：演示建议标题使用具体动作，便于本地预览。
- `packages/ai/src/pedagogy-knowledge.ts` 和 `packages/ai/src/prompts.ts`：约束后续 AI 输出的用户标题表达，提升 prompt 版本。
- `tests/e2e/feedback-monochrome.spec.ts`：黑白配色、模式切换、摘要预览、卡片收起。
- `tests/e2e/redesign-contracts.spec.ts`：更新受影响的用户文案断言。

不新增依赖，不改变 API DTO 和数据库结构。

## 验收标准

1. `/feedback?cycle=cycle-demo` 默认进入快速修改，能切换完整报告。
2. 初始优先建议可以展开，再次点击可以收起。
3. 折叠卡片同时显示原句和推荐改法预览。
4. 原文高亮、建议卡片、筛选和移动端 tab 继续联动。
5. `/today`、`/write`、`/rewrite` 的现有流程不受影响。
6. Chromium 桌面端和移动端无横向溢出，键盘和 axe 检查通过。
7. Web 类型检查、Lint、单测和生产构建通过。
