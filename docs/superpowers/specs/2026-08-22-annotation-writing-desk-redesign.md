# IELTS Writing Coach: “批注写作桌”前端改版设计

**日期：** 2026-08-22

**状态：** 设计方向已批准；规格待用户审阅

**范围：** 在不改变功能、API、状态机、学习记录或路由身份的前提下，重做前端视觉系统、信息层级、页面编排和响应式体验。

## 1. 产品命题

IELTS Writing Coach 不是通用学习仪表盘，也不是题库。它是一张会保存原文、批注、方法、练习和能力证据的数字写作桌。

新版前端要让用户持续看见一条清楚的学习证据链：

> 原文问题 → 修改理由 → 专项方法 → 限时练习 → 闭卷重写 → 迁移证明

视觉记忆点只保留一个：**证据批注线**。它连接原句、建议、教学目标、练习题和后续验证。其他视觉元素保持安静、精确、易读。

## 2. 目标与非目标

### 目标

1. 建立统一、可维护的颜色、字体、间距、圆角、阴影和布局系统。
2. 把 Today 从卡片仪表盘改成“唯一下一步”工作台。
3. 把写作、批改、专项教学、训练卷、重写和对比统一为一条连续的学习体验。
4. 在桌面端充分利用空间；在移动端保持清晰、无横向溢出且不隐藏关键规则。
5. 保留并强化现有可访问性、错误恢复、离线草稿和 AI 局部重试体验。
6. 让普通用户只看到可理解的产品语言；技术配置明确收进高级区域。

### 非目标

1. 不修改数据库、API、AI Prompt、AI 任务、评分逻辑或学习状态机。
2. 不改变任何 cycle、lesson、task 身份参数及其含义。
3. 不新增学习步骤，不重排课程顺序，不改变等待与解锁时间。
4. 不删除现有设置功能；学习数据导出与删除是否保留属于另一项产品决策。
5. 不在第一版引入复杂主题系统、用户自定义配色或装饰性动画。

## 3. 功能冻结边界

新版可以改变 DOM 编排和 CSS，但下列契约必须保持。

### 路由身份

- `/`、`/signin?next=...`、`/join`、`/recover`、`/setup`
- `/today`、`/essays`、`/growth`、`/settings`、`/account`
- `/admin`、`/admin/backup`
- `/write?cycle=...`
- `/feedback?cycle=...`，以及带对应教学身份的 `/feedback?cycle=...&lesson=...`
- `/lesson?cycle=...&lesson=...`
- `/lesson/paper?cycle=...&lesson=...`
- `/rewrite?cycle=...&task=...`
- `/compare?cycle=...`
- `/transfer?cycle=...&task=...`

`cycle`、`lesson`、`task` 是资源身份，不得省略、猜测或替换为通用链接。

行为型 query 同样属于冻结契约：

| 地址                                | 必须保留的行为                                  |
| ----------------------------------- | ----------------------------------------------- |
| `/signin?next=<本地路径>`           | 登录后只允许跳转到安全的站内地址                |
| `/join?token=...`                   | 将邀请 token 消费到内存，随后清除地址栏 query   |
| `/recover?token=...`                | 将恢复 token 消费到内存，随后清除地址栏 query   |
| `/recover?error=INVALID_TOKEN`      | 显示无效或过期状态，随后清除地址栏 query        |
| `/setup?token=...`                  | 将 setup token 消费到内存，随后清除地址栏 query |
| `/today?new-essay=1`                | 直接打开新作文题目选择流程                      |
| `/today?notice=feedback-waiting-ai` | 显示作文已锁定且批改正在排队的提示              |
| `/today?mixed-review=1`             | 进入已安排的混合复测题目选择流程                |

一次性 token 不得写入 localStorage、sessionStorage、IndexedDB、Cookie 或替换后的浏览器历史。

### 学习状态

`首写 → 批改 → 专项教学 → 专项训练卷 → 延迟重写 → 版本对比 → 陌生题迁移 → 后续复测` 的业务语义不变。

- Today 始终只有一个主行动。
- 等待态不能伪装成失败。
- AI 失败只能局部重试，不能抹掉已完成内容。
- 错过重写或迁移窗口必须允许重新安排，且不记学习失败。
- Demo 与 Mock 不得冒充真实语言评分。

### 写作与草稿

- 40 分钟计时、自动保存、Cmd/Ctrl+S、Cmd/Ctrl+Enter、时间到自动提交不变。
- IndexedDB 本地草稿、服务器/本地冲突选择、提交锁定和重复提交竞态处理不变。
- V2 前 35 分钟隐藏个人目标，最后 5 分钟只显示抽象自检项。

### 教学与练习

- 专项教学章节由 AI 动态生成，前端不得固定章节数量或卡片模板。
- 教学练习首次答案不可变；恢复、超时、个性化讲解和重试状态完整保留。
- 训练卷固定 8 题、60 分钟，交卷前不展示答案或批改。
- 训练卷草稿、倒计时、超时锁定和整卷复盘不变。

### 兼容钩子

第一版保留现有可访问名称和自动化锚点，包括：

- `data-app-shell`、`data-sidebar-toggle`、`#primary-sidebar`
- `data-essay-workspace`、`data-essay-card`
- `data-feedback-workbench`、`data-essay-pane`、`data-suggestion-panel`
- `data-issue-card`、`data-issue-highlight`
- `data-teaching-*`
- `.next-task-card`、`.practice-paper-question`

全局中英切换、通知中心、账户菜单、退出登录和侧栏折叠偏好同样属于冻结功能。中英切换只改变界面语言，不翻译 IELTS 题目或用户作文。

## 4. 视觉系统

### 色彩

| Token           |      色值 | 用途                               |
| --------------- | --------: | ---------------------------------- |
| Ink             | `#172033` | 主文字、标题、重要图标             |
| Paper           | `#FCFBF8` | 作文、例句、教学正文               |
| Canvas          | `#EEF1F5` | 应用背景、工作台外围               |
| Annotation Blue | `#1D56A0` | 主行动、批注关联、当前步骤         |
| Evidence Green  | `#2F6D5A` | 有后端证据支持的达标、保持与迁移   |
| Revision Amber  | `#7C531B` | 待修改、提示、即将到期的文字与图形 |

错误色使用固定 `#B4474C`，仅用于真正失败或破坏性操作，不参与装饰。

页面不得自行发明相近颜色。透明度变化从上述 token 派生。

草稿已保存、请求已提交等操作成功使用 Ink 或 Annotation Blue 的中性反馈，不使用 Evidence Green。保存成功不等于能力已掌握。Revision Amber 在 Paper 与 Canvas 上均需满足普通文字 4.5:1 对比度；浅色提示背景从它派生，但文字始终使用深色 token。

### 字体角色

- **界面与中文正文：** Noto Sans SC；400 / 500 / 650 / 700。
- **英文作文与英文例句：** Source Serif 4；400 / 600。
- **时间、词数、分数和小型数据：** IBM Plex Sans；500 / 600。

字体通过 `next/font` 或项目自托管方式稳定加载，不依赖操作系统是否安装。

### 字号与阅读尺度

- 页面标题：40 / 46px 桌面，30 / 36px 移动。
- 章节标题：28 / 36px 桌面，24 / 32px 移动。
- 正文：16px，行高 1.7；长文阅读 17px，行高 1.82。
- 英文作文：17px，行高 1.9。
- 标签与辅助文字最低 12px；主要元信息最低 13px。

### 间距、圆角与阴影

- 间距只使用 4、8、12、16、24、32、48、64、80。
- 圆角只使用 6、10、16；胶囊仅用于真实状态标签。
- 常规内容不使用阴影；浮层和固定操作栏才允许一级阴影。
- 卡片不是默认容器。优先使用留白、分隔线、背景层和排版层级。

## 5. 布局系统

正式学习 AppShell 提供三种布局槽位，页面不再通过负 margin 突破容器；登录、邀请、恢复和首次设置继续使用独立 Entry 外壳。

1. **Focus：** Today、作文列表、账号、设置和管理页面。最大内容宽度 1120px。
2. **Reading：** 专项教学、成长档案。正文 720–760px，可带 220px 目录或证据栏。
3. **Workspace：** 写作、批改、训练卷、版本对比和陌生题迁移。充分使用剩余视口，可达 1440px。

- 不隐藏考试规则、恢复状态或失败处理方式。

## 6. 标志性元素：证据批注线

证据批注线不是装饰，而是跨页面的结构语言：

- 批改：连接原文 mark 与建议。
- 专项教学：标记本节训练的能力与它解决的问题类型，但不定位原作文。
- 训练卷：标明题目是在“识别、修复、迁移还是整合”能力。
- 对比：连接 V1 问题、V2 改变及是否复发的证据。
- 成长：展示全部能力阶段，并区分“正在形成”和“已有验证证据”。

颜色语义固定：蓝色为正在学习，绿色只表示后端证据支持的达标、保持或迁移，琥珀为仍需证明。不能用红色制造学习焦虑。

### EvidenceLink 组件形态

```text
●━━━━━━━ 当前学习目标
端点       连接线       可读状态文字
```

- `active`：实线蓝，表示当前正在学习或当前选中的原文—建议关联。
- `verified`：实线绿，只用于真实评估支持的达标、保持或迁移。
- `revision`：实线琥珀，表示仍需修改或验证。
- `unavailable`：灰色虚线，表示证据尚未生成或当前不可比较。
- `disabled`：无连接线，仅保留可读说明，表示步骤尚不可达。

桌面端允许跨栏连接；移动端降级为条目左侧 3px 竖线和同样的状态文字，不绘制跨屏曲线。找不到精确证据时不画连接线，也不猜测关联位置。线条本身 `aria-hidden`；关系、状态和操作通过现有按钮名称、`aria-describedby` 与正文表达，不能只靠颜色。桌面与移动截图必须证明五种状态使用同一视觉语法。

## 7. 页面设计

### Today：一件事工作台

```text
今天 · 8月22日                           2 篇进行中
┌──────────────────────────────────────────────────────────────┐
│ 当前唯一行动                                                 │
│ 闭卷重写：小学外语启蒙                         40 分钟        │
│ [开始重写]                                                   │
└──────────────────────────────────────────────────────────────┘

我的作文                         本篇证据链
进行中作文列表                   首写—批改—教学—训练—重写—迁移
```

- 主行动占页面视觉中心。
- 多作文切换保留，但降低权重。
- 三项现有统计保留在页面下部的安静证据摘要中；不再使用同权重的大卡片。
- “刷新计划”保留为证据摘要后的次级操作，按钮名称与行为不变。
- AI 排队、失败、阻塞和可重试状态紧邻主行动展示。

### 我的作文：多作文工作区

- 保留最多 8 篇并行作文、公开题、自定义题、题型和话题选择。
- 每篇作文继续使用自己的 `nextTask.href`，不能通过当前页面猜测目的地。
- 桌面采用安静的列表或双列工作区；移动端采用单列，不把作文状态压缩成难读标签。
- 达到上限时保留全部旧作文，并明确说明需要先完成一篇才能新建。

### 写作室与延迟重写：考试桌

- 题目区与编辑区使用两个清楚的纸张层次，不再套入通用卡片。
- 桌面采用 36–40% 题目、60–64% 编辑器；题目 sticky。
- 计时、词数、保存状态形成一条安静状态栏。
- 提交是唯一强色按钮；冲突与恢复操作保持中性色。
- 移动端先显示题目摘要，再显示全宽编辑器；规则可折叠但不能消失。

### 批改报告：批注工作台

- 保留原文与建议双栏、双向联动、键盘行为和移动 tab。
- 左栏像批改稿纸；右栏像编辑批注边栏，减少卡片嵌套。
- 总评与四项分数压缩成页面首部的“评阅摘要”，不抢正文空间。
- 每条建议统一为：问题 → 为什么 → 建议改法 → 可迁移规则。
- 段落优化紧邻对应段落，而不是成为独立 Dashboard 模块。

### 专项教学：编辑式长文

- 保留现有文章宽度、目录 sticky、章节层级和动态内容结构。
- 去掉重复外框，依赖标题、分隔线、例句块和批注线建立层级。
- 教学练习作为文章中的练习停靠点，不改首次答案和个性化讲解状态。
- “开始 60 分钟训练卷”始终在文章末尾可达。

### 专项训练卷：连续试卷

- 从八张大卡改为连续编号试卷；题与题之间使用页规线和留白。
- 顶部突出训练目标、完成数、计时和返回教学；“查看详细批改”仍保留在同一工具区，但使用次级权重。
- 桌面右侧提供紧凑题号导航；移动端使用可横向浏览的题号条。
- 交卷栏显示已答数量，不遮住当前题的选项或输入区。
- 交卷后不改变现有结果分类与展开逻辑。

### 版本对比与成长：学习证据档案

- V1/V2 差异以同一 rubric、原文证据和复发情况组织。
- 分数只是证据的一部分，不作为页面主角。
- Growth 完整展示 diagnosed、practicing、applied、retained、transferred 五级状态，并按时间组织“出现 → 学习 → 重写 → 迁移”的能力记录。
- 只有 retained、transferred 或后端明确返回有效验证证据时使用绿色“已验证”视觉；applied 保持蓝色的阶段性通过语义。
- 没有证据时明确显示“仍需验证”，不使用空仪表盘或伪趋势。

### 设置与账号

- 普通设置分为学习、提醒、AI 服务和数据；每类只显示相关控制。
- Provider、Base URL、模型路由等技术项放入明确的高级区域，但功能不删。
- 账号与安全保持独立页面；退出登录在桌面与移动端都可达。

### 登录、邀请、恢复与首次设置

- 无会话访问站点仍先进入登录页；个人实例的新邮箱自动注册，共享实例仍需要邀请。
- 登录、邀请、恢复和 Setup 使用同一套克制的入口视觉，但各自只保留一个明确主行动。
- 一次性 token 的读取、清除和错误处理不变；页面不重复显示或泄露 token。
- AI 服务连接失败时显示用户可执行的修复建议，不显示内部错误字段。

### 陌生题迁移

- 保留 8 分钟、首次答案冻结、无自然机会、重排和结果状态。
- 页面视觉上延续“证据批注线”，但不展示旧题答案、旧提示或目标答案。
- 评估失败时明确“答案已保存，不是学习失败”，并保留检查设置的入口。

### 管理与运维页面

- Admin、备份和系统状态页面沿用同一 token，但使用更紧凑的运维信息层级。
- 不隐藏真实失败、不展示虚假的“迁移已最新”等结论；状态文案只表达后端实际返回的事实。
- 普通学习者导航不增加管理入口，权限与可见性逻辑保持不变。

## 8. 交互与文案

- 一个动作在按钮、加载状态和完成提示中使用同一名称。
- 学习流程和普通错误提示不显示 job、provider、schema、internal ID 等后台词；AI 高级设置保留用户配置所必需的 Provider、Base URL 和模型路由名称。
- 等待态说明系统正在做什么以及用户现在能做什么。
- 失败态说明什么被保留、如何恢复、是否影响学习结果。
- 动效只用于证据批注线激活、面板切换和状态确认；时长 120–220ms。
- 遵守 `prefers-reduced-motion`，禁止大面积进入动画和装饰性循环动效。
- 通知中心仍按原节奏刷新并保留未读与标记已读行为；视觉上使用紧凑列表，不转成新的任务系统。

## 9. 前端架构

### 保留

- 所有 page 数据加载、client service、API 调用和业务状态。
- WritingRoom、TeachingArticle、Feedback 标注同步及其公开行为。
- 现有 URL、localStorage / sessionStorage / IndexedDB 键。
- 现有 ARIA 名称与测试锚点。

### 新增或重构

- `styles/tokens.css`：唯一基础 token 来源。
- `styles/foundations.css`：重置、字体、焦点、排版。
- `components/shell/*`：导航轨道、上下文顶栏、移动菜单。
- `components/layout/*`：Focus、Reading、Workspace 布局槽位。
- `components/primitives/*`：Button、Status、Surface、Divider、EvidenceLink。
- 页面样式逐步迁入 CSS Modules；`globals.css` 最终只保留 foundations 和少量兼容层。

第一阶段不改组件数据接口。需要改变 DOM 层级时，用现有 props 和状态重新编排。

## 10. 实施顺序与回退

1. 锁定现有功能回归和视觉基线。
2. 建立 token、字体、布局槽位和新版 AppShell。
3. 先完成 Today、写作室、批改报告这一条核心纵向切片。
4. 完成专项教学、训练卷、延迟重写和版本对比。
5. 完成作文列表、成长、迁移、设置、账号、登录与管理流程。
6. 清理无引用旧样式，最后移除兼容层。

所有工作在独立分支完成。每一阶段保持可构建、可测试；若某页尚未迁移，它继续使用旧样式，不出现半完成界面。切换到新版前，保留当前可用提交作为明确回退点。

## 12. 自我批评与修正

最初方向容易滑向“暖白稿纸 + serif + 细线”的通用编辑风格。为避免模板感，本设计做了两项约束：

1. serif 只用于真实英文作文与例句，不用于所有标题；中文 UI 保持清晰的 sans。
2. 视觉记忆点不是纸张纹理或装饰编号，而是与产品真实证据结构绑定的批注线。

因此，新版的辨识度来自学习机制，而不是一套可以复制到任意写作产品的皮肤。
